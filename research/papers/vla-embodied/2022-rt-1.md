# RT-1: Robotics Transformer for Real-World Control at Scale

## Agent brief

Use RT-1 to teach how a real-robot trajectory becomes a transformer training example. The most reusable units are action discretization, visual token compression, task-aware sampling, and autoregressive control. A learning problem should reproduce one unit on synthetic data rather than require the original robot fleet.

## Contribution

- **Changed:** RT-1 demonstrates that a transformer policy can absorb a large, heterogeneous collection of language-conditioned robot demonstrations while retaining practical control frequency. Its design turns continuous action dimensions into discrete tokens and reduces image features to a compact token set before sequence modeling.
- **Evidence:** The reported evaluation is summarized below; the proposed exercises use deterministic small-scale proxies.
- **Not established:** The paper does not establish universal safety, unsupported-embodiment robustness, or equivalence of an educational reproduction.

## Prerequisite concepts

- Behavior cloning and teacher forcing
- Transformer token sequences and causal prediction
- Continuous-to-discrete quantization
- Robot trajectories, control frequency, and closed-loop rollout

## Method map

| Component | Input | Output | Core invariant | Good exercise boundary |
|---|---|---|---|---|
| Observation encoder | RGB frame and instruction | Spatial feature grid | Batch and spatial order are preserved | Validate encoder shapes and preprocessing |
| TokenLearner-style compression | Feature grid `[B,H,W,D]` | Compact tokens `[B,K,D]` | Selection weights normalize over spatial positions | Implement vectorized weighted token selection |
| Temporal transformer | Recent compact tokens | Contextual control features | Padding and time order never leak | Construct history windows and masks |
| Action tokenizer | Bounded continuous action | Ordered integer tokens | Encode/decode share bounds and token order | Implement a reversible action codec |
| Runtime decoder | Predicted tokens | Continuous robot command | Invalid or stale commands are rejected | Build validation and shadow replay |

## Essential equations

For action dimension (j) with range ([l_j,u_j]) and (B) uniform bins, one transparent token codec is

$$
q_j(a_j)=\operatorname{clip}\!\left(\left\lfloor B\frac{a_j-l_j}{u_j-l_j}\right\rfloor,0,B-1\right),
\qquad
\hat a_j=l_j+\left(q_j+\tfrac12\right)\frac{u_j-l_j}{B}.
$$

The autoregressive training objective over action tokens is

$$
\mathcal L_{\text{act}}=-\sum_t\sum_j \log p_\theta\!\left(q_j(a_{t,j})\mid o_{\le t},c,q(a_t)_{<j}\right),
$$

where (c) is the instruction. This notation is pedagogical; an implementation must match the chosen token ordering exactly.

## Visual teaching plan

- **Interactive quantizer:** sliders for action value, bounds, and bin count; show the chosen token, decoded center, and error.
- **Token pipeline diagram:** image plus instruction -> compact visual tokens -> transformer -> per-dimension action tokens -> robot command.
- **Scaling explorer:** vary task imbalance and sampling temperature, then plot the realized minibatch mixture.

## Data and evaluation

- **Reported setting and protocol:** The study uses a large real-robot dataset spanning many tasks, objects, and environments. Evaluation emphasizes seen-task performance, generalization to changed objects/backgrounds/instructions, robustness, and the effect of dataset/model scale. For a small reproduction, use synthetic trajectories and report token reconstruction error plus rollout success in a toy environment.
- **Compute/hardware interpretation:** Reported scale and physical hardware materially affect comparability; do not infer equivalence from a toy run.
- **Educational boundary:** Use synthetic or licensed fixtures and report mechanism-level metrics separately from closed-loop outcomes.

## Limitations and failure modes

- Discrete action bins introduce quantization error and make range calibration important.
- Behavior cloning inherits demonstration coverage and compounding-error limits.
- The original scale and real-robot diversity are not inexpensive to reproduce.
- Aggregate success rates can hide task-specific regressions and unsafe failure modes.

## Implementation decomposition

1. Define an action schema with per-dimension bounds and validation.
2. Fit or configure bin edges using training data only.
3. Implement reversible encode/decode with clipping and boundary tests.
4. Convert trajectories into fixed context windows and masks.
5. Add a small observation encoder and action-token head.
6. Evaluate token accuracy, decoded error, latency, and closed-loop success separately.

## Problem blueprints

### Problem: Quantize RT-1 actions

- **Type:** function
- **Difficulty:** easy
- **Learning objective:** Implement and test this mechanism as an independent, observable skill.
- **Inputs:** float action array, lower/upper bounds, number of bins
- **Outputs:** integer tokens and decoded bin-center actions
- **Fixture:** Deterministic synthetic or openly licensed data matching the declared interface.
- **Grading:** exact boundary behavior, clipping policy, shapes/dtypes, and round-trip error tolerance
- **Paper deviation:** Isolates one mechanism; omits the paper-scale model, data, and physical-robot experiment.

### Problem: Select compact visual tokens

- **Type:** component
- **Difficulty:** medium
- **Learning objective:** Implement and test this mechanism as an independent, observable skill.
- **Inputs:** feature map `[B,H,W,D]`, learned selection logits, requested token count
- **Outputs:** normalized weighted visual tokens `[B,K,D]`
- **Fixture:** Deterministic synthetic or openly licensed data matching the declared interface.
- **Grading:** softmax axis, vectorized weighted sum, gradient flow, numerical stability, and output shape
- **Paper deviation:** Isolates one mechanism; omits the paper-scale model, data, and physical-robot experiment.

### Problem: Build task-balanced batches

- **Type:** pipeline
- **Difficulty:** medium
- **Learning objective:** Implement and test this mechanism as an independent, observable skill.
- **Inputs:** trajectory records with task IDs and lengths; target task mixture
- **Outputs:** deterministic sample weights or sampled indices
- **Fixture:** Deterministic synthetic or openly licensed data matching the declared interface.
- **Grading:** empirical mixture tolerance, seed reproducibility, no invalid indices, and handling of empty tasks
- **Paper deviation:** Isolates one mechanism; omits the paper-scale model, data, and physical-robot experiment.

## MLOps and deployment extensions

- Version action bounds and bin edges with the model; a silent schema mismatch can move hardware incorrectly. Track per-task sampling rates, per-action saturation, decode error, and end-to-end control latency. Add a shadow-mode replay test that runs every candidate checkpoint on frozen observation logs before robot deployment.
