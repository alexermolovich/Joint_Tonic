## Core paper explanation

GR00T N1 separates a vision-language context model from a fast action-generation model for humanoid control. The action system uses a diffusion-transformer architecture trained with action flow matching; architecture terminology should not be confused with a DDPM noise-prediction loss. Its training data combines real robot demonstrations with additional human and synthetic sources, making data representation and embodiment interfaces central parts of the system.

## Execution flow

The vision-language system encodes context, an embodiment-aware action system learns a conditioned flow, and short-step integration generates action chunks. Heterogeneous training data enters through source-specific representation contracts.

### Encode semantic context

Write semantic context as $h=S_2(I,\ell)$ and current proprioception as $q_t$. The action system conditions on both. Training examples must identify their embodiment and supported action channels; a human-video representation is not automatically a robot actuator command.

In the full paper, an inverse-dynamics encoder learns latent actions from video pairs and treats that latent representation as a separate LAPA embodiment. If $x_t,x_{t+H}$ are two frames, write its learned continuous target as $z_t=f_\psi(x_t,x_{t+H})\in\mathbb R^{d_z}$. This latent width $d_z$ is not a robot joint count. [The heterogeneous-batch exercise](/problems/gr00t-heterogeneous-training-batch) only handles direct robot actuator supervision and therefore masks video action labels; learning $f_\psi$ and supervising its latent targets are deliberately outside that exercise.


$$
c_t=(h,q_t,e),
$$

where $e$ identifies the embodiment/interface. This tuple is a teaching description of the conditioning contract. [Validate a Multimodal Robot Episode Schema](/problems/validate-robot-episodes) checks a related bounded data contract before such examples reach a model.

### Learn action flow matching

For clean chunk $A\in\mathbb R^{H\times D}$ and Gaussian noise $E$, an explicit noise-to-data path is

$$
A_\tau=(1-\tau)E+\tau A,\qquad
u_\tau=A-E,
\qquad
\mathcal L=\mathbb E\|V_\theta(A_\tau,\tau,c_t)-u_\tau\|_F^2.
$$

The target is a velocity under this declared convention, not simply $E$. The v1 paper prints the opposite target sign, $E-A$, alongside the stated noise-to-data interpolation; the equation here and [masked-loss exercise](/problems/gr00t-masked-action-flow-loss) explicitly use the path derivative $A-E$. This is a convention choice for a self-consistent teaching computation, not an assertion of checkpoint compatibility. Source-paper and code parameterizations must be checked for time/sign conventions before loading pretrained weights. Masks for unsupported or padded dimensions must exclude those terms from the chosen loss reduction. Data-source weighting is another independent training decision; it must not be hidden in the order of files.

### Integrate a control chunk

A consistent Euler step under the convention above is

$$
A_{k+1}=A_k+\frac{1}{K}V_\theta(A_k,k/K,c_t),
\qquad A_0\sim\mathcal N(0,I).
$$

After $K$ steps, convert the normalized output into the selected robot’s action interface. The semantic model and action system can have different update costs; instrument end-to-end observation-to-command latency rather than reporting only action-head time. [Forward diffusion noising](/problems/diffusion-action-noising) is related background, not an implementation of this flow sampler.

## Why this matters on a robot

Humanoid deployment stresses many coupled channels and heterogeneous data sources. A shared latent representation does not remove morphology, timing, contact, or safety constraints. Report performance by task and embodiment, and distinguish action-model inference speed from the full perception-to-actuation delay.
