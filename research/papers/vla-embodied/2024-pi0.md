## Core paper explanation

π₀ couples a pretrained vision-language backbone with a continuous-action expert. Instead of generating every fine-grained action value as a language token, the action expert learns a conditional vector field that transforms noise into an action chunk. Flow matching supplies a supervised velocity target at interpolated noise/action states. The vision-language backbone supplies context while the action expert handles the continuous control representation.

## Execution flow

Encode the current observation and instruction, train a conditional action velocity on interpolated demonstrations, then integrate that trained field from noise to an action chunk at inference. Training interpolation and inference integration are different computations.

### Build embodied context

Let $c=g_\phi(I,\ell,s)$ denote conditioning derived from images $I$, instruction $\ell$, and robot state $s$. The action expert operates on a chunk $A\in\mathbb R^{H\times D}$, with horizon $H$ and action width $D$. Conditioning and action tokens may use different embedding widths; attention/projection interfaces must make their information flow explicit.

$$
v_\theta:\ (A_\tau,\tau,c)\longmapsto\mathbb R^{H\times D}.
$$

The flow time $\tau$ is dimensionless. It is not the timestamp of one action inside the chunk.

### Train a flow field

The velocity sign below follows [arXiv2410.24164v4, Section IV page 5](https://arxiv.org/pdf/2410.24164v4). Earlier v1 printed the opposite target sign; the pinned v4 equation matches the derivative of the stated noise-to-action path. Local PDF provenance and hashes above are retained unchanged.

Use the explicit noise-to-data convention $\tau=0$ for noise and $\tau=1$ for the clean action. With $E\sim\mathcal N(0,I)$,

$$
A_\tau=(1-\tau)E+\tau A,
\qquad u_\tau=\frac{dA_\tau}{d\tau}=A-E,
$$

$$
\mathcal L_{\mathrm{flow}}=\mathbb E\|v_\theta(A_\tau,\tau,c)-(A-E)\|_F^2.
$$

This is a self-consistent teaching convention; time direction, target sign, and sampler sign must match the implementation or released weights being used. It is not the DDPM noise-prediction objective. [Add Noise to an Action Sequence](/problems/diffusion-action-noising) is a useful contrast: that exercise uses square-root diffusion coefficients and predicts the supplied noise, not this path’s velocity.

### Integrate and execute

For $K$ Euler steps with $\Delta\tau=1/K$, start from $A_0\sim\mathcal N(0,I)$ and update

$$
A_{\tau+\Delta\tau}=A_\tau+\Delta\tau\,v_\theta(A_\tau,\tau,c).
$$

This numerical integration approximates a continuous flow; changing the step count changes both error and inference cost. Unnormalize the resulting actions with the same statistics used in training and send only the controller-supported horizon. More integration steps do not compensate for stale observations or an incorrect action frame.

## Why this matters on a robot

Continuous generation avoids a fixed action-bin resolution, but action units, masks, embodiment differences, and inference deadlines remain central. The same vector field can produce very different physical motion if normalization changes. Evaluate integration-step sensitivity and closed-loop recovery as well as velocity regression error.
