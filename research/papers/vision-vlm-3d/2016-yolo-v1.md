## Core paper explanation

YOLO v1 predicts an image’s object boxes and categories in one network evaluation. A spatial grid divides responsibility: the cell containing an object’s center predicts that object, while multiple box predictors within a cell compete to fit its shape. This design connects localization and classification directly, but its grid assignment limits crowded scenes and small nearby objects. Joint Tonic implements cell assignment, loss components, decoding, overlap, class-aware suppression and evaluation as separate components; its decoder contract is a teaching interface rather than a claim that every later YOLO version uses the same parameterization.

## Execution flow

Inference turns a grid tensor into image-space boxes, combines confidence with class probabilities, and suppresses redundant same-class detections. The training loss below explains where those predictions come from.

### Predict the grid

For an $S\times S$ grid, $B$ boxes per cell, and $C$ classes, the original output has shape $S\times S\times(5B+C)$. Each box carries center coordinates, width, height, and confidence. Its confidence target combines object presence with localization quality:

$$
o=\Pr(\mathrm{object})\operatorname{IoU}(b,b^*).
$$

Here $b^*$ is a target box. The original coordinate objective gives greater weight to localization and compares square roots of widths/heights. A representative responsible-box term is

$$
\lambda_{\mathrm{coord}}\mathbf 1_{ij}^{\mathrm{resp}}
\left[(x_i-\hat x_i)^2+(y_i-\hat y_i)^2+
(\sqrt{w_i}-\sqrt{\hat w_i})^2+(\sqrt{h_i}-\sqrt{\hat h_i})^2\right].
$$

The responsibility indicator selects the predictor assigned to the object; confidence and class terms complete the loss. These normalized coordinates are image quantities, not robot-frame distances.

#### From assignment to a runnable training objective

[Assign ground-truth cells](/problems/yolo-responsible-cell-targets) uses row $r=\lfloor Sc_y\rfloor$ and column $c=\lfloor Sc_x\rfloor$ for normalized object center $(c_x,c_y)$. Its largest-area crowded-cell tie policy is an original teaching convention; one retained target cannot represent every object in that cell.

[Compute the loss components](/problems/yolo-coordinate-objectness-class-loss) receives the responsible predictor and IoU targets explicitly. For occupied cells $\mathcal O$, responsible predictor $b_i$, confidence $c_{ib}$, target IoU $u_i$, class vector $a_i$ and one-hot target $e_{y_i}$,
$$L_{\mathrm{obj}}=\sum_{i\in\mathcal O}(c_{i,b_i}-u_i)^2+\tfrac12\sum_{(i,b)\text{ nonresponsible}}c_{ib}^2,\qquad L_{\mathrm{class}}=\sum_{i\in\mathcal O}\|a_i-e_{y_i}\|_2^2.$$
These dimensionless sums join the square-root coordinate loss above. No-object supervision includes nonresponsible predictors in occupied cells; class supervision does not apply to empty cells.

[Detection evaluation](/problems/detection-precision-recall-map) implements a documented single-IoU, all-point interpolated AP variant with image/class identity and duplicate matching rules. It is not COCO multi-threshold AP. [Accuracy versus edge latency](/problems/detector-accuracy-latency-frontier) analyzes supplied comparable measurements rather than inventing performance results.


### Decode image boxes

For cell column $c$, row $r$, relative center $(x,y)$, normalized width/height $(w,h)$, and image size $(W,H)$ pixels, the teaching decoder computes

$$
u=W\frac{c+x}{S},\qquad v=H\frac{r+y}{S},\qquad
b=(u-Ww/2,\ v-Hh/2,\ u+Ww/2,\ v+Hh/2).
$$

The four output entries are $(x_1,y_1,x_2,y_2)$ pixel coordinates. Width scales horizontal coordinates; height scales vertical coordinates. [Decode YOLO Grid Predictions](/problems/decode-yolo-grid) specifies the exact activation, clipping, and shape conventions used by its tests. Later detector families may use sigmoid/exponential anchor decoding instead, so their weights cannot be silently substituted.


**Implement this component:** [Decode YOLO Grid Predictions](/problems/decode-yolo-grid). Each linked exercise implements its stated bounded subcomponent; completing it is not a full-paper reproduction.

### Score and suppress

A class-specific score is $s_c=o\Pr(c\mid\mathrm{object})$. For two boxes, intersection-over-union is

$$
\operatorname{IoU}(a,b)=\frac{|a\cap b|}{|a|+|b|-|a\cap b|}.
$$

Areas are in square pixels, so IoU is dimensionless. [Compute Pairwise Bounding-Box IoU](/problems/box-iou-broadcast) handles pairwise broadcasting. [Run Class-Aware Non-Maximum Suppression](/problems/class-aware-nms) then keeps the highest-score box and removes lower-score boxes of the same class whose overlap exceeds the declared threshold. Tie order and strict-versus-inclusive threshold comparisons are part of that problem’s contract.


**Implement this component:** [Compute Pairwise Bounding-Box IoU](/problems/box-iou-broadcast) · [Run Class-Aware Non-Maximum Suppression](/problems/class-aware-nms). The decoder uses its declared YOLO-v1 teaching codec; the suppression and overlap utilities are downstream components, not the complete detector.

## Why this matters on a robot

A robot needs spatially stable detections, not merely high image-level classification scores. Duplicate boxes can produce duplicate grasps; an incorrect resize transform shifts all object locations. Preserve the image preprocessing transform, calibrate confidence for the deployment domain, and evaluate detection quality together with inference latency. NMS cannot recover an object the grid representation never separated.
