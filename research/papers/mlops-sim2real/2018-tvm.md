## Agent brief

Use a deliberately small tensor intermediate representation to teach the separation between graph-level rewrites and hardware-specific schedules. Do not attempt to recreate the full compiler.

## Contribution

TVM combines high-level graph optimization, low-level tensor scheduling, and learned cost modeling to deliver performance portability across CPUs, GPUs, embedded processors, and accelerators.

## Prerequisite concepts

- Tensor shapes and common neural-network operators
- Directed acyclic computation graphs
- Memory hierarchy, tiling, and vectorization
- Basic compiler intermediate representations

## Essential theory

Let \(s\) be a legal schedule for computation graph \(G\) on hardware \(h\). Auto-tuning can be expressed as

$$
s^*=\arg\min_{s\in\mathcal{S}(G,h)} C(s;G,h),
$$

where \(C\) is measured or predicted runtime. Graph rewrites must additionally preserve tensor shapes and numerical semantics within an explicit tolerance.

## Method map

| Component | Input | Output | Core invariant | Good exercise boundary |
| --- | --- | --- | --- | --- |
| Graph optimizer | Typed computation DAG | Rewritten or fused DAG | Shapes and numerical semantics are preserved | Implement one legal fusion rewrite |
| Tensor scheduler | Loop nest and hardware constraints | Legal schedule candidate | Every transformation preserves iteration coverage | Implement split/tile/reorder validation |
| Auto-tuner | Candidate schedules and measured/predicted costs | Selected schedule and evidence | Only legal measured candidates can win | Search one bounded schedule space |

- Graph IR and operator fusion
- Tensor-expression language
- Schedule transformations such as split, tile, reorder, and vectorize
- Hardware code generation
- Candidate measurement and learned cost model

## Data and evaluation

Use small convolution and matrix-multiplication graphs with synthetic hardware-cost functions or measured CPU timings. Check semantic equivalence first, then compare operation count, intermediate memory, and latency.

## Limitations and failure modes

The paper's production system is far larger than a course implementation. Measured performance depends on hardware, compiler versions, and search budget; a toy cost model should not be presented as real deployment evidence.

## Implementation decomposition

1. Define typed tensor nodes and shape inference.
2. Implement safe graph rewrites and operator fusion.
3. Generate legal schedule candidates.
4. Estimate or measure candidate cost.
5. Select a schedule and verify numerical equivalence.

## Problem blueprints

| Title | Type | Difficulty | Inputs | Outputs | Grading |
| --- | --- | --- | --- | --- | --- |
| Fuse an Operator Chain | Compiler graph | Medium | Typed operation DAG | Equivalent fused DAG | Legality rules, exact shape preservation, stable serialization |
| Tensor Buffer Reuse | Memory planning | Hard | DAG and tensor sizes | Buffer assignment and peak bytes | No overlapping live tensors, minimal/near-minimal peak memory |
| Tile-Size Search | Optimization | Hard | Loop extents and cost function | Best legal tile tuple | Constraint handling, deterministic tie-break, score optimality |

## Visual teaching plan

- Split view of an unfused and fused computation graph with intermediate-memory totals.
- Interactive loop nest where tile and reorder controls update a simplified cache-cost estimate.
- Tensor-liveness timeline used to demonstrate safe buffer reuse.
- Scatter plot of predicted versus measured candidate cost, highlighting the chosen schedule.

## MLOps and deployment extensions

Profile camera preprocessing, perception, state estimation, and policy inference together. Include accelerator transfer costs, warmup, memory pressure, power mode, and missed control deadlines in the optimization objective.
