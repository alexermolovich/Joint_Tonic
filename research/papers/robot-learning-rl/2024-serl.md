## Core paper explanation

SERL packages practical components for sample-efficient real-robot reinforcement learning: visual off-policy learning, reward specification, reset strategies, and suitable control interfaces. Its contribution is a usable system integration rather than a claim of one new universal RL algorithm.

## Execution flow

### Define control and reward

Actions pass through a declared controller, often designed for compliant contact. Reward can come from a binary classifier, an adversarially updated model, or robot-state logic. A classifier probability $p(\mathrm{success}\mid o)$ needs validation on policy-generated failures, not only curated positives.


**Implement this component:** [Validate Success-Classifier Rewards on Robot Failures](/problems/serl-success-reward-failure-audit).


### Run asynchronous collection and learning

Actor/learner separation lets robot collection continue while the learner revisits replayed transitions. For batch size B, critic Q, reward $r_i$, terminal flag $d_i$, discount gamma and target value $V_{target}$, a bounded description of the critic regression is

$$
y_i=r_i+\gamma(1-d_i)V_{target}(s'_i),\qquad
\mathcal L_Q=\frac1B\sum_{i=1}^{B}(Q(s_i,a_i)-y_i)^2.
$$

States may include images and proprioception; actions retain the controller's declared units. Values and rewards are scalar and use the same reward convention. The equation is a teaching core, not the complete SERL learner with all ensemble, entropy and regularization choices. With B=2, targets[2,0] and predictions[1,2], squared residuals[1,4] give loss2.5. A terminal second sample has no future-value term even when its reset process takes time.

A separate operational measure is the update-to-data ratio $\rho=U/N$, where U is optimizer steps and N newly collected transitions in one reporting interval. U=100,N=20 gives rho5 updates per new transition; it does not say how many unique transitions were sampled. Record actor policy version alongside timestamps to detect stale execution. [Select a Checkpoint with Offline and Rollout Gates](/problems/offline-rollout-checkpoint-gate) is a related evaluation component; it does not reproduce asynchronous SERL training.

The critic core is $L_Q=\mathbb E_D[(Q(s,a)-r-\gamma(1-d)V(s'))^2]$, with the actual algorithm supplying its target details and regularization. Actor/learner separation reduces idle robot time; policy versions and observation/action timing remain traceable.


**Implement this component:** [Merge Online and Demonstration Replay](/problems/serl-merge-replay-sources).

**Implement this component:** [Schedule Actor-Learner Updates](/problems/serl-actor-learner-schedule).

These are bounded operational exercises: replay ingestion merges immutable transition identities and preserves source provenance; the scheduler carries an exact update budget between ticks. Neither implements the distributed learner or its network synchronization. The classifier audit uses supplied predictions and does not train a reward model.


### Reset and evaluate repeatedly

Forward and reset policies solve different objectives. Reset success must return the system to the intended initial-state distribution; otherwise later trials are not comparable. Record reset time and failures alongside training interaction time.


**Implement this component:** [Record Intervention and Reset Statistics](/problems/serl-intervention-reset-statistics).

## Why this matters on a robot

Reliable reward, reset, and controller interfaces often determine whether RL works outside simulation. Reward hacking, reset drift, and asynchronous timing mistakes are system failures even when the loss implementation is correct.
