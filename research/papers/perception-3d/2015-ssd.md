## Core paper explanation

SSD predicts object categories and box offsets at several feature-map resolutions in one pass. Each location uses a set of default boxes with different sizes/aspect ratios, allowing different maps to specialize in different object scales. Training matches ground-truth boxes to default boxes and limits the influence of abundant background examples through hard-negative mining.

## Execution flow

Generate multi-scale default boxes, predict and match offsets/classes, then rank and suppress decoded detections.

### Generate multi-scale defaults

For feature map side $f_k$, location $(i,j)$, normalized scale $s_k$, and aspect ratio $a$, one default box is

$$
c_x=(i+\tfrac12)/f_k,\quad c_y=(j+\tfrac12)/f_k,
\quad w=s_k\sqrt a,\quad h=s_k/\sqrt a.
$$

These coordinates are normalized to the image. Real implementations must specify rectangular-grid handling and the extra square defaults used between adjacent scales. Generating defaults in a different order from the model head silently swaps targets.

### Match and train offsets

A target is matched to appropriate defaults by overlap; a best-match rule ensures a target can obtain a positive default. With $N_+$ positives,

$$
\mathcal L=\frac{\mathcal L_{\mathrm{conf}}+\alpha\mathcal L_{\mathrm{loc}}}{N_+}.
$$

Define the no-positive behavior explicitly instead of dividing by zero. Localization uses center/size offsets relative to each default. [Pairwise IoU](/problems/box-iou-broadcast) supplies the overlap matrix used by a matching exercise.


**Implement this component:** [Compute Pairwise Bounding-Box IoU](/problems/box-iou-broadcast). Each linked exercise implements its stated bounded subcomponent; completing it is not a full-paper reproduction.

### Mine negatives and decode

Sort unmatched defaults by classification loss and keep at most a configured ratio of negatives to positives; SSD uses a3:1ratio in its training recipe. This selects examples by loss, not by raw foreground probability alone. Decode offsets, threshold class scores, and apply overlap suppression. [Class-aware NMS](/problems/class-aware-nms) implements the final duplicate-removal mechanism under its documented ordering and threshold rules.

## Why this matters on a robot

Multi-scale prediction improves coverage, but tiny objects and heavily resized inputs remain difficult. A change to input resolution must be reflected in default-box geometry. Inspect per-scale recall and inference latency rather than treating the dense output as a single undifferentiated tensor.
