## Core paper explanation

SAM 2 extends promptable segmentation to video through streaming memory. A frame encoder produces current image features, memory attention retrieves information from previously processed frames, and a prompt-conditioned decoder predicts the object mask. The prediction is encoded back into memory for later frames. Interactive prompts can correct the tracked object as the video evolves.

## Execution flow

Encode a frame, condition it on object memory and prompts, then update the memory bank with the resulting prediction. Memory state belongs to an identified video/object sequence.

### Encode the current frame

For frame $I_t$, let $F_t=f_I(I_t)$. A point or box prompt must follow the same resize/pad mapping as the frame. Video time $t$ is distinct from feature-grid coordinates. With no video memory, the model behaves as an image segmentation system rather than inventing temporal evidence.

### Attend to object memory

A simplified memory-attention operation is

$$
\tilde F_t=\operatorname{softmax}\left(Q(F_t)K(\mathcal M_t)^\top/\sqrt d+M\right)V(\mathcal M_t),
$$

where $\mathcal M_t$ is the selected memory bank and $M$ masks unavailable entries. The full model also uses positional/temporal information and prompt decoding. Selecting memory frames under a budget changes the available evidence; it must not mix different object identities or videos.


**Planned component problems:** Maintain object-specific video memory; Select memory frames under a fixed budget. These are planned work, not runnable links; titles without a reviewed blueprint remain unreviewed ideas.

### Predict and update memory

An operational recurrence is

$$
\hat Y_t=f_{\mathrm{mask}}(F_t,\tilde F_t,P_t),\qquad
\mathcal M_{t+1}=\operatorname{Update}\bigl(\mathcal M_t,f_{\mathrm{mem}}(F_t,\hat Y_t)\bigr).
$$

$P_t$ contains the current prompts. The recurrence describes interfaces, not a replacement for the paper’s memory-selection policy. A wrong prediction can contaminate future memory, so correction prompts and object-absence behavior need explicit tests.


**Planned component problems:** Evaluate mask drift, absence, and correction recovery. These are planned work, not runnable links; titles without a reviewed blueprint remain unreviewed ideas.

## Why this matters on a robot

Temporal memory can maintain an object through changing views, but drift and occlusion can propagate mistakes. Reset state at sequence boundaries and measure recovery after a correction, not just average per-frame overlap. Memory budgeting and frame latency matter in long robot runs.
